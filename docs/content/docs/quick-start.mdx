## Set up KVM

Sandboxes are hardware VMs, not containers. Linux hosts need **KVM** (`/dev/kvm`); macOS hosts need **Apple Silicon** (Virtualization.framework). `cellard` installs the [microsandbox](https://docs.microsandbox.dev/getting-started/quickstart) runtime on first sandbox use.

If a host fails to start sandboxes, use the platform guides:

### Linux

Confirm the KVM module and device exist:

```bash
lsmod | grep kvm
ls -l /dev/kvm
```

An Intel host usually shows `kvm_intel` and `kvm`; AMD shows `kvm_amd` and `kvm`. If `/dev/kvm` is missing, enable CPU virtualization in firmware/UEFI (and nested virtualization if this host is itself a VM), then load the module:

```bash
grep -E -c '(vmx|svm)' /proc/cpuinfo   # 0 means virtualization is off or hidden
sudo modprobe kvm_intel                # Intel
sudo modprobe kvm_amd                  # AMD
```

glibc must be **2.28 or newer**. The `cellar` service user needs read/write access to `/dev/kvm` — install (next section) adds that user to the `kvm` group.

See the [Linux troubleshooting](https://docs.microsandbox.dev/troubleshooting/linux) page for permissions, nested VMs, and `msb doctor`.

### macOS

Apple Silicon only — Intel Macs are not supported. There is no separate KVM feature to enable; Virtualization.framework is already present.

See [macOS troubleshooting](https://docs.microsandbox.dev/troubleshooting/macos) if sandbox startup fails.

## Install

On each host, install Cellar, create the `cellar` system user, and start the daemon:

```bash
curl -fsSL https://cellar.prodioslabs.in/install.sh | sh
sudo systemd-sysusers
sudo usermod -aG kvm cellar
sudo systemctl daemon-reload
sudo systemctl enable --now cellard
sudo systemctl enable --now cellar-gateway   # optional: HTTP front door for apps
```

See [non-root access](/docs/install/non-root) to run the CLI without `sudo`.

## Initialize the cluster

On the first manager, initialize with that host’s reachable address (defaults: data `/var/lib/cellar`, socket `/var/run/cellar/cellar.sock`):

```bash
sudo cellar init --advertise-addr 192.0.2.10:17946
```

## Join a worker

Print a ready-to-run join command on the manager:

```bash
sudo cellar join-token worker
# → cellar join --token CLLRN-1-… 192.0.2.10:17946
```

On the worker (after install and `enable --now cellard` as above):

```bash
sudo cellar join --token CLLRN-1-… 192.0.2.10:17946
```

Managers join the same way with the **manager** token (and should pass `--advertise-addr` / `--raft-addr`).
